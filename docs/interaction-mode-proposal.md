# 交互模式可见性方案

日期：2026-10-28。用户已确认实施；实现与测试记录见[开发日志](development-log.md)。

## 当前问题

`ctx.mode` 已保存当前模式，但 `ctx:mode_buttons()` 生成两个外观相同的普通按钮，画布没有常驻模式标识，用户难以预判下一次点击的作用。

## 推荐反馈

1. 用例控件顶部采用互斥分段按钮：“绘制”和“调整”。当前项使用实心背景、明确边框及“当前”标记，其他项保持普通外观；颜色之外仍能辨认状态。
2. 画布左上角固定显示“绘制模式 · 多边形”或“调整模式”，用小面积、鼠标穿透的标签呈现，不阻挡绘制和拾取。
3. 模式标签下显示一条动态提示：绘制时提示下一步和落点进度，调整时提示选择、主体平移或控制点调整；不再同时堆叠两种模式的说明。
4. 绘制使用十字光标；调整时空白处使用箭头、主体使用移动光标、控制点使用手形。临时平移显示“临时平移”，结束后恢复原模式反馈。

示例：

| 场景 | 常驻文字 | 操作提示 |
| --- | --- | --- |
| 多边形绘制 | 绘制模式 · 多边形 | 已落点 2/5，继续单击落点 |
| 调整但未选择 | 调整模式 | 单击选择图形，拖动主体平移 |
| 已选择对象 | 调整模式 · 已选中多边形 | 拖主体平移，拖控制点调整，Esc 取消 |

## 操作约定

- 点击已经激活的模式不做任何操作，不清除未完成点列或选中对象。
- 切换模式保留已经完成的对象，取消未完成绘制和拖动预览；如取消了预览，短暂提示原因，避免弹窗打断操作。
- Esc 取消当前操作，保持模式；模式切换不进入撤销历史、不修改文档脏状态。
- 每个画布独立显示自身模式；F5 后显示脚本默认模式，撤销重做保持现有模式规则。
- 首轮实现以上反馈；快捷键可作为后续可配置扩展，避免与自定义用例的按键冲突。

## SDK 与模块边界

以实际 `ctx.mode` 为唯一状态源，按钮、画布标签和提示共同读取它，最迟下一帧同步。保持现有 `ctx:mode_buttons()` 调用兼容，三个内置实例自动获得反馈。直接调用 `ctx:set_mode()` 仍保留 v1 的取消/重置契约；按钮层忽略对已激活模式的点击。

自定义用例通过 `ctx:register_mode(id, {label=..., hint=..., cursor=...})` 声明名称、提示和光标；未声明的模式显示其标识，不误标为绘制或调整。运行时输出通用模式信息，界面负责颜色、位置和光标，保持运行时对 ImGui 无依赖。十字使用绘制层指针，隐藏系统箭头，不修改上游后端。

## 验收重点

- 无需点击或悬停即可辨认模式，颜色不是唯一线索。
- 新建、按钮切换、用例自动切换、多标签切换和 F5 后，按钮与画布标识一致。
- 再次点击当前模式不取消半成品；真正切换、Esc 和撤销重做遵循上述契约。
- 在文字控件获得焦点时不触发额外画布操作；画布标签不接管鼠标事件。
- 标准模式与自定义模式都可验证，测试和截图场景纳入现有工程入口。

设计参考：[状态可见性](https://www.nngroup.com/articles/visibility-system-status/)、[颜色之外的状态线索](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)。后者作为桌面界面的设计参考，不据此宣称 Web 可访问性认证。
