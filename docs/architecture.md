# 架构与 SDK 设计

状态：首版已实现；实现决定和验证情况见下文及测试记录。日期：2026-10-27。

本文件记录总体设计。实际接口见 [SDK 使用说明](sdk.md)，验证情况见[测试记录](testing.md)。产品行为以[需求规格](requirements.md)为准，选择依据见[决策记录](decisions.md)。

## 1. 技术组合与依赖边界

| 组成 | 用途 |
| --- | --- |
| C++ | 宿主、文档、历史、几何辅助与渲染适配 |
| Win32 | 窗口、输入、系统文件对话框 |
| Direct3D 11 | 图形设备、交换链与渲染后端 |
| Dear ImGui | 应用界面、用例控件和基础绘制 |
| 标准 Lua | 用例执行、控件逻辑、模式与自定义算法 |
| CMake / CTest | 构建组织与测试调度 |

主要第三方依赖仅 Dear ImGui 1.91.9b 和 Lua 5.4.8。不修改上游源码，使用 CMake FetchContent 获取固定版本并校验哈希，源码和编译缓存放在构建目录，不进入 Git。首次配置需要网络，也可以指定已解压的离线源码路径。发布时复制许可证。Lua 绑定直接使用 C API；文档、历史和交互辅助自行实现。

不因本机安装了 Qt、Python 等工具而引入相应运行时。不默认引入脚本绑定框架、图形编辑框架或插件框架。质量工具采用开发期 Catch2 和可选 Google Benchmark，不链接应用、不安装到发布目录；依赖决定见 D26。

官方资料：[Dear ImGui](https://github.com/ocornut/imgui)、[平台与渲染后端](https://github.com/ocornut/imgui/blob/master/docs/BACKENDS.md)、[Lua](https://www.lua.org/about.html)、[Lua 参考手册](https://www.lua.org/manual/)。

## 2. 模块职责

```text
Win32 / Direct3D 11
        │
桌面宿主：用例列表、标签、命令、文件操作、错误面板
        │
用例会话：Lua 环境 + 文档 + 临时交互状态 + 历史 + 视图
        │
Lua SDK：控件、对象、绘图、事件、模式、几何、编辑事务
        │
Lua 用例：数据定义、控件、默认模式与具体交互逻辑
```

- **宿主层**：维护图形设备、应用生命周期、全局菜单、标签和通用命令；不包含三角形或曲线用例的专属逻辑。
- **会话层**：管理单个实例的运行环境、状态、历史、脏标记和文件路径，确保实例隔离。
- **SDK 层**：提供可组合的公共能力，协调常规编辑与低层自定义逻辑。
- **用例层**：通过 Lua 定义完整演示；不要求编译动态库或修改宿主代码。

优先按职责分为少量目标和模块，不把每个概念拆成独立工程或动态库。

实际实现按 `core`、`runtime`、`platform`、`render`、`app` 组织；CMake 目标检查单向依赖，脚本检查 include/import 越界。Lua SDK 由几何、事务、对象、交互和控件模块组合。完整目录、接口与所有权见[模块与目录](modules.md)，代码与注释规则见[代码规范](coding-style.md)。

## 3. 用例发现与生命周期

用例以目录组织，入口为 `<用例目录>/<用例名>/main.lua`，可包含辅助 Lua 模块。入口返回表，提供 `id`、`name`、`data_version`、`default_mode` 与回调。SDK 随宿主提供；用例目录按本次 `--cases-dir`、本机记忆、exe 旁内置示例的顺序选择，不自动搜索仓库。界面可以打开目录和编辑脚本，目录切换只更新列表，已打开画布保持来源绑定。当前三例为可配置多边形、可变阶数贝塞尔和按种类交互绘制的 Gallery；旧标识保持兼容。

每个标签拥有独立 Lua 环境。同一用例打开多份时，不共享可变全局状态。辅助脚本的加载路径以用例目录为基准，避免依赖启动时工作目录。

`drawer.*` 是 SDK 保留模块命名空间，从 SDK 目录加载；用例自身的普通辅助模块仍从用例目录加载。

生命周期包含：创建环境、加载模块、初始化数据与默认模式、处理控件与输入、绘制、结束会话。加载文档时，先验证对应插件和数据，再恢复状态。F5 对当前实例创建候选环境，初始化成功后再替换；失败保留原会话。

界面将 F5 命名为“应用脚本修改 F5”，明确会重置当前画布和历史；“更新用例列表”只更新发现结果，已打开实例保持运行。F5 成功同步当前用例的列表名称并清除旧失败提示，不执行其他用例的初始化。

## 4. SDK 公共能力

### 4.1 组合式接口

SDK 同时提供三组可组合能力：

1. **基础绘制**：世界坐标下的图元、样式、文本、辅助线与临时覆盖层。
2. **对象编辑**：标准图形、自定义对象、命中检测、选择反馈和控制点。
3. **交互辅助**：模式、事件分发、拖拽生命周期、取消与编辑事务。

标准对象可直接复用编辑行为；自定义对象可以提供绘制、命中和控制点逻辑。临时计算过程和辅助图形可以直接绘制，不必全部变为持久化对象。

### 4.2 接口草案

以下为接口概览，具体签名、事务规则和示例见 SDK 使用说明：

```lua
return {
    id = "example.triangle",
    name = "三角形",
    data_version = 1,
    default_mode = "draw",

    on_init = function(ctx) end,
    on_ui = function(ctx) end,
    on_event = function(ctx, event) end,
    on_draw = function(ctx) end,
}
```

概念上的 `ctx` 提供对象、状态、控件、绘图、视图、交互模式和编辑事务等入口。输入事件提供统一数学坐标下的位置、按钮、按键和修饰键；画布外的界面操作不应误触发绘制。

控件直接由 Lua 调用，例如：

```lua
if ctx.ui.button("调整模式") then
    ctx:set_mode("edit")
end
```

不通过大型声明式 UI 系统描述简单按钮和参数。控件参数若属于可编辑数据，其更改必须经 SDK 事务进入历史；模式、选择和视图状态保持独立。

## 5. 状态与历史

| 状态类别 | 示例 | 保存 | 进入撤销历史 |
| --- | --- | --- | --- |
| 持久化编辑数据 | 图形、顶点、自定义算法输入、用例参数 | 是 | 是 |
| 视图 | 中心位置、缩放 | 是 | 否 |
| 临时交互状态 | 模式、选择、悬停、未提交预览 | 否 | 否 |
| 执行资源 | Lua 回调、渲染资源、文件路径以外的运行对象 | 否 | 否 |

持久化自定义状态限定为有限数值、布尔、字符串及无循环的数组和键值结构；函数、执行资源和对象引用不可直接保存。对象之间的持久化关联应采用稳定标识。

SDK 提供统一编辑事务。常规对象编辑由 SDK 自动组织事务；用例自行修改持久化数据时，显式使用同一机制。

拖拽流程为“开始事务 → 预览更新 → 松开提交”，取消则回滚。首版使用完整数据快照，最多保留 100 步，并按序列化大小约 64 MiB 限制历史保留。以正确性、低复杂度和千级场景为目标，不承诺任意 Lua 变量自动追踪。

脏标记按保存点与持久化数据内容比较；视图变化本身不产生脏标记，但下次保存时写入最新视图。

## 6. 文档与错误处理

文档采用版本化 UTF-8 JSON，保存文档格式版本、用例标识与数据版本、标准对象、自定义数据、持久化参数及视图。加载文档只读取数据，不执行文档内嵌代码。

写入应避免失败时破坏已有文件；读取应先完成解析、基本校验和候选会话恢复，再打开新标签。遇到缺失插件或不支持的数据版本时明确报错，不猜测转换。

Lua 调用通过保护调用入口执行，错误面板记录文件、行号和可获得的调用栈。编辑事务中的脚本错误应回滚未提交变化。错误不能使其他标签的状态被修改。

## 7. 渲染与性能策略

- 统一使用数学世界坐标，由视图变换为屏幕坐标；文本保持正常阅读方向。
- 屏幕命中容差应随缩放转换，避免控制点在不同缩放下难以选择。
- 绘图与交互使用同一坐标变换，覆盖高 DPI 和窗口尺寸变化。
- 提供批量绘制和常用几何计算入口，减少逐点 Lua / C++ 往返。
- 优先测量千级对象场景，再按瓶颈增加缓存、裁剪或空间索引。
- 贝塞尔支持 1–32 阶，渲染与拾取共享自适应折线，细分最多 1024 段；绘制配置不改变已存在对象的控制点数量。
- 普通闭合贝塞尔保留 n+1 个实际控制点，`closed=true` 时首尾坐标必须一致且至少三阶；创建收集 n 次点击。SDK 的 `bezier` 模块处理接点约束，独立 `bezier_ui` 模块复用控件；交互层通过公开手柄接口拾取和移动，渲染器只消费规范数据并连接描边接缝。缺少标记的旧对象按开口处理。
- `smooth=true` 是闭合对象的可选 C1 约束，至少四阶：两侧控制点关于接点对称，切向非零。创建收集 n−1 次点击；手柄拖动使用原始快照，整体平移后保持镜像。core 的 `ValidateBezierJoin` 负责几何约束校验，SDK 负责构造与编辑；渲染和拾取继续消费同一实际控制点，不为平滑新增绘图分支。
- Lua 自行实现的密集算法不自动具有原生性能；性能描述必须区分计算、脚本绑定、命中和渲染开销。

## 8. 首版实施决定

以下是在用户确认范围内确定的实施细节，已落入代码与 SDK 文档：

- C++17、CMake 3.24+；Dear ImGui 1.91.9b、Lua 5.4.8；MSVC 静态运行库。
- 用例入口为 `main.lua`，自定义对象通过 `ctx:register_type` 注册；`on_clear` 在统一清空事务内处理额外状态。
- 文档扩展名 `.drawer.json`，根字段 `format`、`format_version`、`case_id`、`case_version`、`state`、`view`。格式版本为 1，文档上限 16 MiB。
- 持久化状态保留 `objects`、`params`、`next_id`；事务不可嵌套，回滚后状态表可能替换。
- 历史为快照，容量见上；加载从新历史起点开始，恢复视图并使用默认交互模式。
- 中键或空格+左键平移，滚轮以鼠标为中心缩放，Home 适应内容，Esc 取消，Delete 删除；常用 Ctrl 命令与 F5 见 README。
- 窗口渲染自动化测试与截图已执行；文件对话框、确认弹窗及跨显示器 DPI 的人工验收保持待办。

后续改变既定产品行为仍需重新确认，接口扩展与内部优化应同步维护此文档和回归测试。
