# 贝塞尔曲线闭合方案

日期：2026-10-28。用户已确认首轮只做普通闭合，平滑接点留作后续增强；本轮人工验收已通过并授权本地提交。结果见[测试记录](testing.md)。

## 目标与现状

为现有任意阶贝塞尔用例提供简洁的闭合创建和编辑能力，继续支持撤销重做、保存加载、脚本重载和多画布隔离，不新增依赖。

方案提出时，`BezierPoint` / `FlattenBezier` 已能计算首尾控制点重合的曲线，渲染与拾取共用细分结果，但缺少闭合创建入口、持久化标记及编辑约束。本轮已补齐这些能力，保持单段、1–32 阶的对象模型。

## 推荐交互

| 位置 | 控件或反馈 | 行为 |
| --- | --- | --- |
| 新曲线设置 | `曲线形式：开口 / 闭合` | 默认为开口，仅影响后续创建；切换取消未完成预览，并显示原因 |
| 闭合绘制 | `3 阶闭合 · 已落点 1/3` | n 阶点击 n 个独立控制点，自动补上与起点重合的末端；实时预览回到起点的曲线 |
| 调整面板 | `选中曲线：3 阶 · 已闭合` | 始终显示选中对象自身的状态，与新曲线设置分开 |
| 选中开口曲线 | `闭合曲线` | 将末端合并到起点，阶数保持不变；提示形状会变化且可撤销 |
| 选中闭合曲线 | `断开接点` | 解除首尾联动，不立即移动曲线；提示“拖动接点可拉开末端” |
| 闭合接点 | 一个明显的接点手柄 | 标注“起点/终点”；拖动同时更新首尾，不出现重叠编号或意外拉开 |

闭合与断开均为一次编辑事务。断开后两个端点起初重合，接点优先拾取末端，拖开后分别显示两个手柄。断开不会恢复闭合前的末端位置；需要恢复原形时使用撤销。拖动主体仍整体平移，其他控制点保持现有编辑方式。

普通闭合至少提供 3 阶；1–2 阶首尾重合只会形成点或往返线段，不能围成区域。新建设置切换到闭合时，低于 3 阶自动调至 3 阶并说明；选中低阶旧对象时给出原因，不暗中改变对象阶数。

首轮不叠加填充、自动吸附或新快捷键，保留现有连续创建、Esc 取消及模式反馈习惯。

## 闭合与平滑的区别

推荐首轮支持普通闭合：保证 `P[n] = P[0]`，接缝允许拐角。曲线本身回到起点，保持单段贝塞尔含义。

平滑闭合需额外约束接缝两侧切向。若提供，建议作为闭合后的独立选项，明确采用 G1 或 C1，并定义相邻控制点联动规则。依据端点导数公式可推得：三阶单段曲线在首尾重合且切向平滑时控制点共线，因此非退化平滑闭环至少需要四阶；不应让默认三阶的“平滑”选项生成退化图形。

参考：[贝塞尔端点导数与闭合条件](https://pages.mtu.edu/~shene/COURSES/cs3621/NOTES/spline/Bezier/bezier-der.html)。

## SDK 与模块边界

- 对象保留 n+1 个实际控制点，增加布尔 `closed`；闭合时最后一点是首点的坐标副本。缺少标记的旧对象按原语义加载，不依据坐标重合自动认定闭合。
- `drawer/bezier.lua` 管理闭合转换和首尾联动，`drawer/bezier_ui.lua` 提供两个示例共用的控件；用例只组织业务流程。`ctx:set_bezier_closed(object,closed)` 在调用者事务内操作对象，具体接口见 [SDK 文档](sdk.md)。
- 创建、预览、控制点移动、整体平移和文档加载共同保持闭合约束；保存及加载时校验标记类型和首尾一致性，非法数据不得静默改形。
- 渲染、拾取、采样点与高亮使用同一组实际控制点；闭合描边正确处理接缝连接，不增加直线封口。保留当前细分误差和段数上限。
- 绘制设置与对象状态独立；改变新建设置不得批量转换既有曲线。发布 SDK 与示例同步更新，修改用例本身仍无需编译宿主。
