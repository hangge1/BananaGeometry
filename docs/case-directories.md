# 用例目录与脚本编辑

## 统一的加载规则

开发与发布都通过明确的用例目录加载脚本，取消向上搜索 Git 仓库的隐式切换。首次启动使用 exe 旁的 `cases/`；“打开用例目录”允许选择任意包含用例子目录的文件夹，例如仓库根目录的 `cases/`。

用例目录结构为 `<目录>/<用例>/main.lua`，辅助模块和资源可放在各用例目录中。SDK 随宿主提供，外部用例目录不需要复制 SDK。

界面显示当前列表目录（悬停可查看完整路径），以及当前画布实际绑定的完整脚本路径。“使用内置用例”返回当前 exe 旁的示例。

## 切换、扫描与 F5

- 切换目录只更新列表，不关闭、重置或迁移已打开画布。
- 每个画布始终绑定创建它的脚本路径和宿主 SDK；F5 从该路径重新加载。
- 不同目录出现相同用例 ID 时，旧画布的重载不能改写当前目录的列表条目。
- “更新用例列表”重新扫描当前目录；“应用脚本修改 F5”重置并重新加载当前画布，未保存数据沿用保存/放弃/取消流程。
- 目录不存在或不可访问时显示诊断，不静默改用其他脚本。空目录可正常打开，添加用例后更新列表。

## 本机偏好与启动参数

用户通过界面选择的目录保存在本机 LocalAppData 下的 Drawer 偏好文件中，不写进发布目录。选择内置示例时记住“使用内置”，不保存其绝对路径。

`--cases-dir <目录>` 显式覆盖本次启动的目录，不改写本机偏好；自动化 smoke 模式忽略本机偏好，避免读取个人用例。旧 `--workspace <目录>` 保留为 `<目录>/cases` 的兼容入口，SDK 仍来自宿主。

偏好损坏时显示原因并使用内置示例；已记住的目录被移动或删除时显示原目录与错误，允许重新选择。

## 编辑当前脚本

“编辑当前脚本”打开当前画布绑定的 `main.lua`，即使列表已经切换到其他目录，也不会打开同名副本。优先使用 Windows 的“编辑”关联；未配置时使用记事本。保存后按 F5 应用修改。

编辑器启动失败时报告原因，不修改画布、历史或文件。目录选择、偏好持久化和编辑器启动各自位于独立模块，并通过可替换的桌面操作接口验证取消、失败与路径绑定行为。

原生接口参考 Microsoft 的[目录选择对话框](https://learn.microsoft.com/en-us/windows/win32/shell/common-file-dialog)和[编辑动作](https://learn.microsoft.com/en-us/windows/win32/shell/launch)说明。
